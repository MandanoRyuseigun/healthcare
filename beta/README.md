# うちのレシピ帳 β（Puter.js 版・最小版）

claude.ai の外で、知り合いに試してもらうためのウェブアプリ。`index.html` 1ファイルだけで動く。

- ログイン・AI・保存は [Puter.js](https://developer.puter.com/) を使う。運営は API キーもサーバーも持たない
- AIの費用は、利用者それぞれの Puter アカウントの毎月の無料枠から使われる（User-Pays モデル）
- AIは **節約モード固定**（`AI_MODEL = "claude-haiku-5-5"`）。Puter がこのモデル名を受け付けないときは Puter の標準モデルで再試行し、使用量の記録に「＊」が付く
- データは利用者の Puter アカウントの中（キー：`recipe:<id>`、`menu:<id>`、`kitchen`、`usage:YYYY-MM`。写真は Puter のファイル `photos/` に長辺1280pxのJPEGで保存）。運営からは見えない

## できること（最小版）

| 画面 | 中身 |
|---|---|
| 提案 | 食材・何人分（1〜6人）・買い足し予算・補足から提案。作るものを1つ選ぶ（または選ばない）と1品、2つ以上選ぶと献立（例：主菜＋副菜）。献立は食材の使い回し、段取り（作る順番）、献立全体の買い足しをまとめて1回のAI呼び出しで出す。買う理由、買わない方法、残りの保存方法も出す。種類が合わなければ1回だけ自動で再試行 |
| レシピ帳 | 保存した1品と献立の一覧、詳細、削除。「手入力で追加」で手持ちのレシピを登録・編集（料理名、カテゴリ、何人分、時間、材料、作り方、メモ、写真）。作った料理の写真を追加・削除でき、一覧に最新の写真が出る |
| 調理環境 | いつも作る人数（提案の初期値）、器具と常備品を保存し、提案に使う |
| 使用量 | 今月のAI回数、1回あたりの送信・受信の文字数、日時ごとの記録。中身は記録しない |

| 提案の履歴 | 直近10件の提案を残し、押すとその案をもう一度表示して保存できる（保存済みは印が付く） |
| ご意見 | 画面下の「ご意見・不具合を送る」から、種類と内容を運営に送る |

まだないもの：相談、レシピへの反映、みんなのレシピ、アレルギー登録。

## 利用状況・ご意見の集め方（運営だけが見る）

- 送り先は **Netlify Forms**（公開しているサイトの機能）。見られるのは Netlify にログインした持ち主だけ
- `usage`（利用状況）：番号（`uid`、Puter に保存したランダムな値で名前ではない）、`event`（open／suggest／menu／save／manual／photo）、`version`、`detail`（カテゴリ名など）。料理の中身・写真・調理環境は送らない。利用者は「使用量」画面で止められる
- `feedback`（ご意見）：番号、バージョン、種類、内容、送った画面
- **最初に1回だけ必要な設定**：Netlify のサイト設定で「Forms」の「Form detection（フォームの検出）」を有効にしてから、もう一度フォルダを上書きする（検出が無効だと送信が受け付けられない）
- **見方**：Netlify の「Forms」で `usage` / `feedback` を開き、CSV をダウンロード → `admin.html` を開いて CSV をドラッグすると、利用者数・回数・日ごと・利用者ごと（直近14日の利用日数＝判断1の目安）・ご意見を集計して表示する。集計はブラウザの中だけで行う
- 新しい料金体系の Netlify アカウントでは、フォームの受信は無料・無制限と報じられている（2026年4月〜）。旧体系だと月100件まで

## 置き場所（公開のしかた）

静的なファイル1つなので、無料で置ける場所ならどこでもよい。例：

- **Netlify Drop**：`beta` フォルダをブラウザにドラッグするだけで公開できる
- **Cloudflare Pages**：無料で、商用でも使える
- **GitHub Pages**：このリポジトリが公開リポジトリか、有料プランなら使える

`https://` のアドレスで開くこと。パソコン内のファイルを直接開くと、ログインが動かないことがある。

## 動作確認でやったこと

- 作業環境から Puter に接続できないため、Puter の代わりの仮の部品を入れてブラウザで確認した（スマホ幅）
- 確認した流れ：ログイン → 調理環境の保存 → 提案（節約モデルの指定、調理環境が指示に入ること）→ 保存 → 一覧と詳細 → 使用量の記録
- **本物の Puter ではまだ動かしていない**。最初の確認ポイント：
  1. ログイン画面が出るか、日本語か英語か
  2. 提案が返ってくるか（モデル名が受け付けられるか。使用量の種類に「＊」が付いたら標準モデルで動いている）
  3. 保存したレシピが、ページを開き直しても残っているか
  4. 写真を追加して、開き直しても表示されるか（写真は Puter のファイル保存を使う。無料の容量は200MB）

## 無料枠の見積もりのしかた

1. 本番の Puter で、節約モードの提案を10〜20回使う
2. 「使用量」の回数と、Puter の画面（puter.com の設定 › 使用量）の減り方を記録する
3. 1回あたりの消費 ＝ 減った量 ÷ 回数
4. 献立は1回の呼び出しで返す量が1品より多いので、「使用量」の種類ごと（1品・献立）に分けて1回あたりを見る
5. 「普通に使う人」の月の回数（目安：提案15・相談15・反映5・保存方法5 ＝ 40回）に掛けて、無料枠に収まるかを見る
6. 「ふつう」「しっかり」モードは、公開価格の比で節約モードの約20倍・それ以上かかる見込み。必要なら少数回だけ試して確かめる
